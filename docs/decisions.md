# Decisions

| Area | Decision | Rationale | Current sources |
|---|---|---|---|
| Bootloader | Use systemd-boot templates first. | It is simple, native to systemd-based Arch installs, easy to inspect, and keeps recovery entries straightforward. No disk partitioning or automatic UUID guessing is performed. | `system/boot/loader.conf`, `system/boot/infinity.conf`, `system/boot/infinity-fallback.conf`, `system/boot/README.md` |
| Boot splash | Use mkinitcpio plus Plymouth templates. | Plymouth gives a coherent boot surface while mkinitcpio remains the standard Arch initramfs path. The hook template avoids assuming encryption or resume. | `system/boot/mkinitcpio-plymouth.conf.template`, `system/plymouth/infinity.plymouth`, `system/plymouth/infinity.script` |
| Greeter | Use greetd with ReGreet as primary and tuigreet as recovery. | greetd is Wayland-friendly and session-focused; ReGreet supports themed graphical login, while tuigreet gives a lower-risk fallback if graphics fail. | `system/services/greetd.toml`, `system/services/greetd-tuigreet-recovery.toml`, `desktop/greeter/regreet.toml` |
| Locker | Use hypridle plus real hyprlock. | The lock boundary must be a real locker, not a shell overlay. The lifecycle is dim, lock, then display off. | `system/power/hypridle.conf`, `desktop/lockscreen/hyprlock.conf` |
| Quickshell | Use one modular scene with per-screen surfaces and singleton state. | Shared tokens and services keep the rail, overlays, OSD, wallpaper, and appearance previews in one motion system without creating a giant QML file. | `desktop/quickshell/shell.qml`, `desktop/quickshell/services/`, `desktop/quickshell/surfaces/` |
| Theme engine | Use JSON theme bundles and a standard-library Python CLI with atomic writes and whole-operation rollback. | Themes must be deterministic, dependency-light, previewable, and safe to apply to a target config tree without invoking live apps. | `desktop/themes/schema.json`, `desktop/themes/nocturne.json`, `desktop/themes/aurora.json`, `desktop/themes/signal-archive.json`, `bin/infinity-theme`, `tests/test_theme_rollback.py` |
| Package strategy | Keep official Arch package manifests grouped by concern and AUR separate. | Package lists are data, not script logic. Conditional graphics packages are documented rather than globally forced. | `system/packages/*.official.txt`, `system/packages/aur.txt`, `docs/hardware.md` |
| Deployment | Use declared mappings with conflict backups and a deployment manifest. | Target writes must be plan-visible, repeatable, scoped, and recoverable while preserving user override intent. | `deployment/mappings.tsv`, `bin/infinity-deploy`, `docs/deployment.md` |
| Runtime testing | Use nested Hyprland for desktop feedback and snapshot-mode QEMU for system integration. | Nested testing is fast and can prove shell/theme/workspace behavior without touching live dotfiles; QEMU is slower but preserves the boot, service, greeter, and authentication boundaries. | `launch-nested.sh`, `bin/infinity-qemu-smoke`, `docs/runtime-testing.md` |
| Service enablement | Create a reviewed fixed set of descriptor-safe target links in a trusted offline root. | Direct links cannot contact the host manager and avoid implicit unit aliases or companion enablement. A canonical root-owned path, full validation, no-follow traversal, conflict preservation, atomic logging, and idempotent reruns keep the privileged target boundary inspectable. | `system/services/enabled-system-units.tsv`, `installation/stages/services.py`, `installation/lib/safe_fs.py`, `tests/test_service_enablement.py` |
